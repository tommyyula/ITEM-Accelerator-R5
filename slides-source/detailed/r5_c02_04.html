ISS 对标：在现有底座上，哪些需求能用积木组合出来ISS benchmark: which needs can be composed from blocks on the existing platform

很多需求以前不是做不了，而是投入的人工工时太多、ROI 不够，一直排不上。底座上的业务对象、接口和常用组件齐备之后，Agent 能低成本、快速地把它们组合成应用，把数字化推进到过去覆盖不到的地方。Many needs were never impossible, only too costly in engineering hours to justify. Once the platform has its business objects, APIs and common components in place, an Agent can compose them into apps quickly and cheaply, taking digitisation where it never reached.

会中直接提问并确认Ask and confirm in the room

  • Q1 哪些需求因为工时投入大、ROI 不高一直没做，但用现有对象、接口和组件就能组合出来？Which needs were shelved because the effort outweighed the return, yet can be composed from existing objects, APIs and components?
  • Q2 哪些环节还靠纸面、Excel 或口头传递，适合先做一个低风险的试点？Which steps still run on paper, spreadsheets or word of mouth, and suit a low-risk pilot first?
  • Q3 缺积木的需求缺在哪一层：对象、接口还是组件？由谁来补？Where a block is missing, which layer is it—object, API or component—and who adds it?
  • Q4 哪些动作必须由人确认？谁发布、谁审批、谁授权回退？Which actions need a human to confirm? Who publishes, approves and authorises rollback?

每个问题当场记下 Owner、涉及的系统/环境和证据位置。For each question, record the Owner, system/environment and evidence location on the spot.

讨论Discussion挑一个 ISS 过去因 ROI 不高而搁置的需求，当场拆一遍：它用到哪些对象、接口和组件？哪些已有，哪些要补？Take one ISS need shelved for poor ROI and break it down on the spot: which objects, APIs and components does it use? Which exist, and which must be added?
