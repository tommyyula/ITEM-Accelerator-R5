背后的机制：懂业务、守权限、用积木、先试后发What makes it work: knows the business, keeps access, builds from blocks, tries before release

直接让 AI 写页面，会遇到四个问题：字段对不上、权限过大、每个需求重写一遍逻辑、生成即上线。这四件事都交给 WMS 已有的机制。AI-written pages hit four problems: wrong fields, too much access, logic rewritten for every need, and shipping whatever is generated. All four are handed to existing WMS mechanisms.

01 · KNOW

懂业务Knows the business

难点PROBLEM不懂字段与接口，看着对、跑不通。Without WMS fields and APIs, it looks right but does not run.

做法APPROACHAgent 长在 WMS 内部：Item Ontology 描述对象、流程、规则与配置；按操作索引的接口目录和 Skill 告诉它该调哪个接口，目录里没有的不编造。The Agent lives inside WMS: Item Ontology describes objects, processes, rules and configuration; an operation-indexed API catalog and Skills say which API to call, and nothing outside it is invented.

02 · ACCESS

守权限Keeps access

难点PROBLEMAgent 权限过大，或页面直接查表越权。The Agent holds too much access, or pages query tables directly.

做法APPROACH用用户委托的令牌，用户做不了的 Agent 也做不了；页面取数走只读 View，在沙箱里运行；每次写入记下页面与版本。It uses the user's delegated token, so it can do nothing the user cannot; pages read through a read-only View in a sandbox; every write records page and version.

03 · BLOCKS

用积木Builds from blocks

难点PROBLEM每个需求建一张表，各自重写库存逻辑。Each need adds a table and rewrites inventory logic.

做法APPROACH三层存储（Context · Lines · Records）不建表；Move Inventory 等标准步骤封装扫描、托管和库存流水，组装、补货、坏货处理都能复用。Three-layer storage (Context · Lines · Records) needs no tables; standard steps such as Move Inventory wrap scanning, custody and stock transactions, reused for assembly, replenishment and damage.

04 · RELEASE

先试后发Tries before release

难点PROBLEM生成即上线，出错难回退。Generated means live, and mistakes are hard to undo.

做法APPROACH草稿 → 试运行 → 即时迭代 → 有权限的人发布；测试环境导出定制包，生产导入一律为草稿；每个版本保留，可停用、可回退。Draft → trial → iterate on the spot → an authorised person publishes; test exports a package, production imports it as a draft; every version is kept and can be deactivated or rolled back.

换场景时可复用本体、步骤与发布机制；货况映射、角色权限、接口副作用必须重验。以上机制已在 ITEM WMS 本地环境实现。A new scenario reuses the ontology, steps and release; condition mapping, roles and API side effects must be revalidated. These mechanisms run in the ITEM WMS local environment.
